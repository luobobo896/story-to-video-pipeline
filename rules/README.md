# 规则库（项目无关，可复用）

> 版本 `v1.0` · 定位：**与具体剧本、题材、模型无关的约束集合**。随模板复制到任何新项目，直接生效。

## 为什么单独放

规则和项目记录是两种东西，混在一起两边都废：

- **规则**：跨项目不变。写成"出现 X 判为 Y，应改为 Z"，可以直接拿来当检查项和提示词约束。
- **项目记录**：每个项目都不一样。实测数据、阈值校准、具体镜头号，只对自己的项目有效。

所以本目录只放规则；项目的实测与校准写在 `docs/` 下，并引用这里的编号。

## 每条规则的固定结构

```
编号 · 名称
  问题现象    ← 会看到什么
  判定标准    ← 什么条件下判为不合格（尽量可量化）
  修正要求    ← 具体改成什么
  适用范围    ← 哪些镜头适用
  依据        ← 为什么这么定
```

## 阈值分两类，别搞混

| 类型 | 标记 | 含义 | 新项目怎么用 |
|---|---|---|---|
| **硬阈值** | `[硬]` | 有实测数据支撑，跨模型基本稳定 | 直接用，不用重新标定 |
| **软阈值** | `[软]` | 经验值，受画风、模型档位、题材影响 | **新项目前 3 个镜头必须先做校准样本**，把实测值写进项目 `docs/` 的校准表，再决定是否沿用 |

> 这条区分很重要：把软阈值当硬阈值用，会在换风格时误杀合格素材；把硬阈值当软阈值用，等于没规则。

## 三类用法

1. **写分镜时**——对照规则填 `shots.csv` 字段。规则里提到"必须填写"的字段，空着就是不合格。
2. **生成后**——按 `docs/06` 的 QA 十项逐项核对，命中规则的镜头标 `status=regen`。
3. **自动拦截**——能被量化的规则已经写进 `tools/check_consistency.py`，跑一次就报出来，不靠人记。

## 规则怎么加

新增规则必须带**依据**。依据只有三种合法来源：

1. 本机实测数据（写清样本量、模型、参数）
2. 公开的物理/生理常数（附数值与单位）
3. 同行的可查证实测（附出处）

**"我觉得应该这样"不算依据。** 没有依据的写进项目 `docs/` 当经验备注，不进规则库。
